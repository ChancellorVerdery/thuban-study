**Shared change requests:** none

**Notes.** Design decisions worth knowing: (1) Graph sync is one-directional per source to avoid echo loops: the page's expressionsChanged merges into session.graphExpressions (keeping tutor styling on tutor rows), tutor tool calls mutate the session and forward to the GraphWebView controller directly, and the full list is (re)sent on page ready; there is no onChange(graphExpressions) → setExpressions round trip. (2) AnswerResultsSheet shows canonicalStudent always but canonicalExpected only for correct / equivalentButConditionFailed verdicts so a wrong attempt never reveals the answer (the spec asked for canonical forms; this keeps the 'never reveal' rule). (3) StudyState is kept in a static [ClassID: StudyState] on ClassSession (extensions cannot add stored properties); entries for deleted classes are pruned on access. (4) Web controllers live in StudyState so graph/calculator/transcript state survives section switches and pane toggles; pages re-send their content on 'ready'. (5) The calculator falls back to the MathLive/MathEngine calculator automatically when the Desmos key is empty (configure(forceFallback:)). (6) StudyView registers only .checkAnswers and .showHint; regenerate/next/toggles use the shell defaults. Real Claude/Desmos network calls were not exercised; no API keys added. Existing crash reports in ~/Library/Logs/DiagnosticReports (14:54) predate this build's launch (16:04) and are unrelated.
